# WP_002 — Topper Management: Modal de procesamiento y nuevos estados

## Context

WP_001 implementó la captura de audios y las órdenes con un flujo automático: al procesar un audio, la orden se creaba con datos hardcodeados (sin input del usuario). WP_002 reemplaza ese flujo con un modal de entrada de datos al procesar, introduce tipos de estado más adecuados al negocio real (En Progreso, Entregado, Pagado, A Crédito, Expirado), y añade tracking de pagos (efectivo vs crédito, fecha de expiración de crédito).

No hay backend — todo sigue en memoria con signals.

**Implementado:** 2026-06-19. **Estado:** Completo ✓

---

## Status types

**Audio:** `'Pendiente' | 'Procesado'`
**Orden:** `'En Progreso' | 'Entregado' | 'Pagado' | 'A Crédito'`
**Display-only (calculado):** `'Expirado'` — se deriva en tiempo de render si `isCredit && !isPaid && creditExpiration < today`. No se persiste en el tipo.

## Cambios clave respecto al plan original

### `cake-toppers.service.ts`
- Tipos renombrados: `CaptureStatus` → `AudioCaptureStatus`, `CakeToppersOrder` → `TopperOrder`, `CakeToppersOrderStatus` → `TopperOrderStatus`
- `topperTheme` reemplazado por `topperName` en `TopperOrder`
- `paymentType: 'Cash' | 'Credit'` reemplazado por `isPaid: boolean` + `isCredit: boolean` + `creditExpiration?: string`
- `processCapture()` reemplazado por `createOrderFromCapture(captureId, data)` — recibe los datos del modal completos
- Mock data actualizado a los nuevos tipos (4 capturas, 6 órdenes)

### `process-order-modal/`
- Usa `NgbActiveModal` de `@ng-bootstrap/ng-bootstrap`
- **Fix crítico:** la asignación de `capture` desde `ref.componentInstance.capture = capture` ocurre *después* de `ngOnInit`, por lo que se usó un **setter `@Input()`** en lugar de `OnInit` para inicializar `clientName` en el momento correcto
- Campos: clientName (pre-filled, editable), topperName, createdAt (hoy), status (locked "En Progreso"), price, hasDelivery + deliveryCost (condicional), isPaid, isCredit (condicional a `!isPaid`), creditExpiration (condicional a `isCredit && !isPaid`)
- `isValid` requiere topperName, clientName y price > 0

### `quick-capture.ts`
- Agrega filtro por status (pills: All / Pendiente / Procesado)
- `router` expuesto como público (necesario para el template — botón "Ver pedidos")
- `openProcessModal(capture)` abre `ProcessOrderModal` con `size: 'lg', backdrop: 'static', centered: true`
- `statusKey()` usa `.normalize('NFD').replace(/[̀-ͯ]/g, '')` para manejar acentos en las claves i18n

### `orders.ts`
- `effectiveStatus(order)` devuelve `'Expirado'` si el crédito venció
- Constante `TODAY` calculada una sola vez al cargar el módulo
- `statusKey()` también usa normalización de acentos

### Traducciones
- Eliminadas todas las keys antiguas (`Confirmed`, `In_Design`, `In_Production`, etc.)
- Nuevas keys de `status.*`: `Pendiente`, `Procesado`, `En_Progreso`, `Entregado`, `Pagado`, `A_Credito`, `Expirado`
- Nueva sección `modal.*` con todos los labels del formulario (EN + ES)
- `orders.*` actualizado: quitado `theme/paymentType/cash/credit/deliveryYes`, agregado `topperName/paid/creditDue/pendingPayment`
