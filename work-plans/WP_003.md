# WP_003 — Migración de almacenamiento de audio a Azure Blob Storage (Azurite)

## Context

Las capturas de audio se guardan actualmente en disco local (`wwwroot/uploads/audio/`) y se sirven vía `UseStaticFiles()`. WP_003 migra ese almacenamiento a Azure Blob Storage, corriendo localmente contra el emulador **Azurite** (el usuario lo levanta manualmente; connection string estándar `UseDevelopmentStorage=true`, puertos por defecto). Es un paso hacia un modelo de almacenamiento más realista sin incurrir en costos/config de Azure real todavía.

**Estado:** Planeado — pendiente de implementación.

---

## Decisión de diseño

Se evaluaron dos enfoques:
- **(A) Proxy vía la API** — el endpoint de upload guarda solo el nombre del blob y devuelve una URL relativa (`/api/audio-captures/audio/{blobName}`); un nuevo endpoint GET descarga el blob y lo transmite de vuelta.
- **(B) URL directa del blob** — guardar la URI pública de Azurite directamente en `AudioFileUrl`, requiriendo contenedor público y un cambio en el frontend.

**Se eligió (A).** No requiere cambios en el frontend (el `audioSrc()` en `quick-capture.ts:67-69` ya arma `${environment.apiUrl}${capture.audioFileUrl}` con URLs relativas), mantiene el contenedor privado (sin acceso público anónimo), y la forma de la URL se mantiene estable incluso si en el futuro esto apunta a Azure real en vez de Azurite.

**Nota sobre range-requests:** para que el scrubbing de `<audio>` siga funcionando, las descargas deben usar `BlobClient.DownloadContentAsync()` (stream con seek) en vez de `DownloadStreamingAsync()` (stream forward-only), ya que el range processing de ASP.NET Core solo se activa si el stream es seekable.

---

## Cambios backend (`dotnet-backend/BakeryParty.Api/`)

1. **NuGet:** `dotnet add package Azure.Storage.Blobs` (desde `BakeryParty.Api/`).

2. **Connection string** — agregar a `appsettings.Development.json` (actualmente vacío):
   ```json
   { "ConnectionStrings": { "AzureBlobStorage": "UseDevelopmentStorage=true" } }
   ```

3. **Nueva abstracción de storage** en `Services/` (carpeta actualmente vacía):
   - `IAudioStorageService.cs` — `UploadAsync(Stream, blobName, contentType)` y `DownloadAsync(blobName) -> AudioBlobResult?` (record con `Stream Content, string ContentType`).
   - `AzureBlobAudioStorageService.cs` — envuelve `BlobServiceClient`, contenedor `"audio-captures"` (privado, sin acceso público), usa `DownloadContentAsync()` + `.Content.ToStream()` para descargas seekable.

4. **`Controllers/AudioCapturesController.cs`:**
   - Inyectar `IAudioStorageService` (quitar `IWebHostEnvironment env`, ya no se usa).
   - `UploadAudio`: reemplazar la escritura a disco por `storage.UploadAsync(...)`; devolver `{ url = "/api/audio-captures/audio/{blobName}" }` en vez de `/uploads/audio/{fileName}`.
   - Agregar acción `GET audio/{blobName}` que llama a `storage.DownloadAsync`, devuelve 404 si no existe, o `File(content, contentType, enableRangeProcessing: true)`.
   - `GetAudioExtension` sin cambios.

5. **`Program.cs`:**
   - Registrar `BlobServiceClient` (singleton, desde connection string `AzureBlobStorage`) y `IAudioStorageService` (singleton).
   - Reemplazar la línea de `Directory.CreateDirectory(...uploads/audio...)` por `await blobServiceClient.GetBlobContainerClient("audio-captures").CreateIfNotExistsAsync()` (usando un scope corto, ya que `Program.cs` top-level soporta `await`).
   - **Mantener `app.UseStaticFiles()`** — costo cero, preserva reproducción de capturas viejas en la DB local que aún apunten a `/uploads/audio/...`. Las capturas nuevas ya no usan ese path.

No requiere migración de EF Core — `AudioCapture.AudioFileUrl` sigue siendo `string?`; solo cambia la forma del valor.

## Cambios frontend

Ninguno. `CakeToppersService` y `quick-capture.ts` siguen funcionando sin modificaciones porque el backend sigue devolviendo una URL relativa de la misma forma general.

2. `dotnet run` desde `dotnet-backend/BakeryParty.Api/` — confirmar arranque limpio y que se crea el contenedor `audio-captures`.
3. `ng serve` desde `angular-frontend/`.
4. Probar la app (grabar/subir un clip en Quick Capture, guardar, verificar que `POST upload-audio` devuelve la nueva forma de URL `/api/audio-captures/audio/{guid}...`, reproducir y confirmar que el audio suena y el scrubbing funciona — 200/206 en Network tab).
